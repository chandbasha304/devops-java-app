1. HTTP vs. HTTPS: The Architectural & Security Paradigm

HTTP (HyperText Transfer Protocol) transmits plain ASCII text over cleartext TCP packets on Port 80. Anyone with access to intermediate network switches or routers can intercept, read, or modify this data.

🛡️ The Three Core Security Pillars of HTTPS (Port 443)
  • Confidentiality (Privacy): All headers, URIs, query parameters, cookies, and JSON payloads are strongly encrypted. Eavesdroppers only see unintelligible binary ciphertext.
  • Integrity (Tamper-Proof): Cryptographic Message Authentication Codes (AEAD / GMAC) guarantee that no packet can be altered in transit without immediate connection termination.
  • Authentication (Identity Verification): Proves the server owns the specified domain and private key, verified by cryptographic digital signatures from a trusted Certificate Authority (CA).

2. Cryptographic Foundations: Asymmetric vs. Symmetric

TLS utilizes a hybrid cryptographic model to combine the security of asymmetric encryption with the microsecond speed of symmetric encryption:

Property Asymmetric Encryption (RSA / ECC) Symmetric Encryption (AES-GCM / ChaCha20)
When Used During initial TLS Handshake During Data Transfer Phase
Key Structure Key Pair (Public Key + Private Key) Single Shared Secret Session Key
Algorithms RSA-2048, ECDSA (P-256) AES-256-GCM, ChaCha20-Poly1305
Primary Role Server Identity & Key Exchange High-speed encryption of HTTP payload
Performance Computationally intensive (Math exponentiation) Ultra-fast (Hardware CPU acceleration `AES-NI`)

2.1 The Mathematical Engine of RSA-2048

The security of RSA-2048 is rooted in the Integer Factorization Problem:

  1. Prime Selection: Choose two massive distinct prime numbers p and q (1024 bits each).
  2. Modulus: n = p × q (2048 bits long / ~617 decimal digits).
  3. Euler's Totient: φ(n) = (p - 1)(q - 1).
  4. Public Exponent: e = 65537 (Fermat prime F4).
  5. Private Exponent: d ≡ e⁻¹ (mod φ(n)) → d is kept strictly secret on the VM.
  6. Encryption Formula: Ciphertext = (Message)^e mod n (Performed with Public Key).
  7. Decryption Formula: Message = (Ciphertext)^d mod n (Performed ONLY with Private Key).

4. Pin-to-Point TLS 1.3 Handshake Walkthrough

  1. ClientHello (Client → Server): Client sends supported TLS versions (1.3), cipher suites (TLS_AES_256_GCM_SHA384), a 32-byte Client Random, and its ephemeral ECDHE public key share.
  2. ServerHello (Server → Client): Server selects the cipher suite, responds with a 32-byte Server Random, and sends its own ECDHE public key share.
  3. Key Derivation: Both client and server compute the identical Master Secret using Diffie-Hellman math.
  4. Encrypted Extensions & Certificate: Server sends its X.509 certificate (selfsigned.crt) encrypted with the newly derived handshake keys.
  5. Finished: Both sides confirm integrity with HMAC hashes and switch to full AES-256-GCM symmetric encryption for all HTTP requests.

5. Step-by-Step VM Implementation

Step 1: Generate the RSA-2048 Private Key & Certificate in One Command

sudo mkdir -p /etc/nginx/ssl
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/selfsigned.key \
  -out /etc/nginx/ssl/selfsigned.crt \
  -subj "/C=US/ST=California/L=SanFrancisco/O=DevOpsCorp/CN=136.64.138.242"
🔍 Command Flag Analysis:
  • req -x509: Generates a self-signed X.509 certificate directly, bypassing the intermediate CSR step.
  • -nodes: (No DES) Creates an unencrypted private key so NGINX can boot without human password entry.
  • -days 365: Valid for 1 full year.
  • -newkey rsa:2048: Creates a 2048-bit RSA key pair simultaneously.
  • -keyout & -out: Specifies exact destinations for the private key and public certificate.

Step 2: Lock Down Private Key Permissions

sudo chmod 600 /etc/nginx/ssl/selfsigned.key
sudo chmod 644 /etc/nginx/ssl/selfsigned.crt

6. Production NGINX HTTPS & SSL Termination Configuration

Edit /etc/nginx/sites-available/default:

# 1. Redirect all HTTP Port 80 to HTTPS Port 443
server {
    listen 80 default_server;
    server_name _;
    return 301 https://$host$request_uri;
}

# 2. HTTPS SSL Termination Server Block
server {
    listen 443 ssl http2 default_server;
    server_name _;

    ssl_certificate /etc/nginx/ssl/selfsigned.crt;
    ssl_certificate_key /etc/nginx/ssl/selfsigned.key;

    # Protocols & High-Security Ciphers
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers on;
    ssl_ciphers 'ECDHE-RSA-AES256-GCM-SHA384:ECDHE-RSA-CHACHA20-POLY1305:ECDHE-RSA-AES128-GCM-SHA256';

    # SSL Session Optimization
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    # Security Headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}

Step 3: Test and Reload NGINX

sudo nginx -t
sudo systemctl restart nginx
